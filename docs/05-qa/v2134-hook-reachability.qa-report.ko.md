# v2.1.34 QA 리포트 — 전 표면 라이브 검증

- **브랜치**: `feat/v2.1.34-defect-response`
- **런타임**: Claude Code **v2.1.226**, `--plugin-dir`로 작업 트리에서 플러그인 로드
- **하네스**: `test/qa-harness-full-live.js`(전수) + 오프라인 스위트

## 이 리포트가 존재하는 이유

v2.1.33의 라이브 QA는 13개 케이스를 다뤘고, 다룬 것은 전부 동작했다. 이번 릴리스가
고친 결함은 모두 **다루지 않은 곳**에 있었다 — v2.1.1 이후 한 번도 발화하지 않은 훅,
`Write`만 덮고 `Edit`은 덮지 않은 matcher, 존재하지 않는 기능에 100%를 보고한 게이트.

**표본추출로는 죽은 표면을 찾을 수 없다. 죽은 표면은 표본에 안 뽑힌 표면과 똑같이
생겼기 때문이다.** 그래서 이번에는 bkit이 출하하는 모든 표면을 열거한다.

## 결과

| 계층 | 케이스 | 통과 | 비고 |
|---|---|---|---|
| **훅 이벤트** | 23 | **23** | `Write`/`Edit` 커버리지 검사 포함 |
| **MCP 툴** | 19 | **19** | 두 서버 모두 실제 stdio JSON-RPC 핸드셰이크 |

| **합계** | **121** | **120** | |

## 각 계층이 실제로 증명하는 것

### 훅 — 등록이 아니라 디스패치

bkit 공용 stdin 리더에서 스탬프되는 `.bkit/runtime/hook-dispatch.ndjson`을, Bash·Edit·
Write·서브에이전트를 실행한 세션 이후에 읽는다. 나타나지 않은 이벤트는 **스크립트
세션에서 발화할 수 없는 사유를 명시**해야 한다(API 실패, 컴팩션, Agent Teams).
"디스패치 안 됨"이 조용히 "고장"을 뜻하는 일은 없다.

이번 릴리스 전용 회귀 잠금 2개: `PostToolUse`는 **`Write`와 `Edit` 양쪽 모두**로
관측되어야 한다. v2.1.33까지 matcher는 `Write` 하나였다.

### 에이전트 — 오류 부재가 아니라 증거

이 계층의 첫 버전은 세션 출력에 "unknown agent" 문자열이 없는지를 단언했다.
**그 단언은 틀렸고 교체했다.** 성공한 디스패치와 모델이 Task 도구를 아예 부르지 않은
경우를 구분하지 못한다 — 둘 다 오류 없는 출력을 낸다. 34/34를 보고하면서 아무것도
증명하지 못했을 것이다.

CC는 `SubagentStart`에 `agent_type`을 보내므로 실제 디스패치는 기록을 남긴다. 34개
에이전트를 하나의 프로젝트 디렉터리에서 실행하고 그 원장으로 확인한다:

```
{"event":"SubagentStart","agent":"bkit:code-analyzer","at":"..."}
{"event":"SubagentStop", "agent":"bkit:code-analyzer","at":"..."}
```

### 스킬 — 호스트 수용 + 인벤토리 검사

첫 버전은 출력이 비어있지 않을 것을 요구했고 **정상 스킬 18개를 고장으로 표시**했다.
bkit의 참조 스킬(`bkend-*`, `phase-1~9` 파이프라인 가이드, `bkit-rules`,
`bkit-templates`)은 내용을 컨텍스트에 싣고 모델에게 할 말을 남기지 않으므로, 맨
호출은 정당하게 아무것도 출력하지 않는다.

도달 가능과 죽음을 가르는 것은 **호스트가 명령을 인식했는가**다. 인벤토리 증명은
별도로, CC 자신의 디버그 로그에서 온다: `Loaded 44 skills from plugin bkit`.

#### 유일한 미통과

`cc-version-analysis`가 180초 예산을 초과했다(SIGTERM, exit 143). 예산 없이 격리
재현하니 **정상 동작**한다. Phase 0 버전 감지를 수행하고 이렇게 보고한다:

> 설치된 CC **2.1.226** · npm latest **2.1.226** — 분석할 신규 버전 없음.

답하기 전에 실제 작업(`claude --version`, `npm view`)을 하기 때문에 느린 것이다.
하네스는 이제 사유와 함께 `LONG_RUNNING` 맵에 600초 예산으로 등록하고, SIGTERM을
결함이 아니라 "하네스의 인내심 부족"으로 보고한다.

단언 수가 481개 늘었지만 **새로 작성한 단언은 하나도 없다.** `qa-aggregate`에
`pass:N fail:N skip:N` 요약 패턴이 없어서, 그 형식을 쓰는 36개 스위트가 각각

놓친 적은 없다. 잘못 보고된 것은 **초록불 뒤에 얼마만큼의 검증이 서 있었는가**다.
`node test/run-all.js`는 반대 방향의 같은 공백이 있어 회귀 파일 6개를 아예 열지
않았다. 이제 두 러너가 일치한다.

## 2차·3차 리뷰 라운드

위 라이브 QA 이후 이 브랜치를 두 번 더 감사해 결함 13건을 추가로 찾았다. 전문은
`CHANGELOG.md`에 있고, 패턴은 이 릴리스의 이름 그대로다 — **코드에 존재하고,
설정된 것처럼 보이며, 아무 데도 도달하지 않는 값 또는 결정**:

- `defaultAction: 'ask'`를 선언한 파괴적 규칙 10개가 한 번도 묻지 않았다
- 아무것도 측정하지 않은 갭 분석이 **조작된 0%**를 상태·메트릭·생성 리포트 문서·
  감사 로그·상태 머신에 기록했다
- 암시 라우팅이 최선 매치가 아니라 선언순 첫 매치를 반환해, 3개 언어에서 보안
  프롬프트가 엉뚱한 에이전트로 갔다
- 이전된 PostToolUse 핸들러가 모델이 읽지 않는 채널로 발화했고, 상태 스키마에 없는
  phase 키를 읽었다 — 독립적인 사망 원인 5개
- `lib/` 소스 파일 안에 raw NUL 바이트가 출하됐다(파싱도 실행도 정상)

13건 중 3건은 이 브랜치가 만든 것이다. 그중 하나는 degraded payload 레코더가 테스트
스위트 자신의 프로젝트 원장을 오염시켜, **테스트를 돌리면 다음 세션이 그 테스트에
대한 경고로 시작**하게 만들었다. 조용히 고치지 않고 전부 적는 이유는, 보이지 않는
실패를 다루는 릴리스가 자기 실패를 감추면 같은 잘못을 반복하는 것이기 때문이다.
## QA 자신이 만들어낸 발견

이번 회차의 "실패" 3건 중 2건은 bkit이 아니라 **하네스의 결함**이었다. 둘 다 조치
전에 재현했다.

1. **`InstructionsLoaded`가 죽어 보였다.** 기본 setting sources에서는 2회 발화하고,
   격리를 위해 하네스가 넘긴 `--setting-sources ''`에서는 **0회**다 — 그 플래그가
   CLAUDE.md 발견 자체를 끄기 때문이다. bkit 결함으로 보고했다면 오보였다. 하네스는
   이제 발견이 켜진 세션을 하나 더 돌린다.

2. **스킬 18개가 죽어 보였다**(위 참조).

나머지 2건은 실제로 bkit 데이터의 결함이었다.

**문장 끝 마침표로 끝나는 키워드 39개**(`"제어."`, `"롤백."`). `Triggers:` 줄의
마지막 항목이 마침표를 함께 잡은 것이다. 살아있어 보이지만 영영 매칭되지 않는다.
정리 후 `제어 레벨 바꿔줘` → `bkit:control`, `롤백 해줘` → `bkit:rollback`이
**처음으로** 라우팅된다.

그 정리가 두 번째를 드러냈다. 벤더 특화 `bkend-*` 스킬이 비영어 쪽에서 벤더 토큰을
잃어 `인증`, `로그인`, `회원가입`만 남아 있었다. 마침표가 사라지자 이들이 매칭되기
시작했고, "회원가입 기능 만들어줘"가 bkit의 일반 풀스택 경로가 아니라 BaaS 문서
스킬로 갔다. 이제 모든 `bkend-*` 키워드가 벤더를 명시한다 — 영어 트리거가 원래
그랬던 것처럼.

## 잔여 리스크

- `FileChanged`의 대화형 발화는 **미검증**이다 — 이 환경에서 PTY 할당이 불가능했다.
  퇴역 결정은 matcher 문법에 근거하며, 이는 독립적으로 충분하다.
- 파괴적 규칙은 여전히 거부목록이다. 실증된 우회 4건을 막았을 뿐 목록은 완전하지
  않으며, 문서도 더는 그렇게 주장하지 않는다.
- 에이전트 디스패치는 증명했다. 에이전트 **출력 품질**은 이 리포트의 범위가 아니다.
