being blocked, a harmless command running, and `session_title` reaching a hook).
That is a sample, not verification. The maintainer asked whether *every* bkit
feature had been exercised with `--plugin-dir .` and `claude -p`. It had not.
This report covers the full surface.

## What this QA found that the earlier pass did not

Restoring the gate turned CI red on the first push. Every failure was
pre-existing and had been invisible:

| Failure | Root cause |
|---|---|
| `v200-workflows` WF-001..018, `automation-first-v2` AF-021, `docs-equals-code-v2` DC-001..003 | Asserted against `.bkit/workflows/*.yaml`, which is git-ignored and generated by nothing — the files existed only on machines where someone had created them by hand. Now shipped in `templates/workflows/`. |
| `core-modules` CM-017/018 | Expected `parseHookInput` to return `''` for absent fields; it returns `null`. **Failing locally too** — the file reports on stderr and the aggregator captured stdout only, so the parser counted zero failures for a file reporting two. |
| `security-by-default` SB-013 | Asserted the starting trust score *clears* the L2 threshold. Passed only where a profile had accumulated (50) and failed on a fresh checkout (38 vs 40) — and pointed the wrong way for this suite. Inverted: a fresh profile must start below L2. |
| `v2112` L3-017 | Required a non-zero token ledger. CI writes ledger rows but makes no model calls, so zero is correct there. |

## Known limitations

Stated rather than hidden:

- The widened heredoc guard matches a pipe anywhere inside the heredoc body, so
  writing *about* these bypass forms in a heredoc trips it. Encountered while
  committing this work.
- `PATH_TRAVERSAL` as implemented means "outside `process.cwd()`", which covers
  ordinary work in another directory, so it stays advisory rather than blocking.
- Timing budgets in `test/performance/` widen under the aggregator. They are
  smoke checks against pathological regressions, not benchmarks.
- Live QA exercises representative skills across categories rather than issuing
  all 44 slash commands; all 44 are verified structurally in Layer 1.

## Process note

This QA was executed with purpose-built harnesses rather than through the
`/bkit:qa-phase` skill. The skill wraps L1–L5 test planning and generation,
which this release already has in the form of the 354-file suite plus the two
harnesses above; running it would have produced a plan for tests that exist. The
substantive requirement — that every bkit surface is exercised with
`--plugin-dir .` and `claude -p` — is met and recorded here.
