## 6. 검증 범위의 한계 (정직한 서술)

1. **검사 대상은 macOS x86_64 바이너리 1종**입니다. Linux · Windows · arm64
   빌드는 검사하지 않았습니다.
2. **`GIT_SHA`가 실제로 바뀌었습니다**(`d4b76e8c…` → `e140b328…`, 빌드 간격 약 5시간).
   즉 upstream에는 **실제 커밋이 존재**합니다. 이번 분석의 주장은

### ERRATA-35-1 (HIGH, 방법론) — `strings` 차분은 의미 변화의 증거가 아니다

분석 중 `strings -n 5` 집합 비교에서 **1,315 added / 1,226 removed** 가 나왔고,
"순증 리터럴 1건: `Push when Claude decides`"라는 결론에 도달할 뻔했습니다.

**이는 전량 오탐이었습니다.**

- `Push when Claude decides` 는 **양쪽 바이너리에 모두 존재**합니다
  (원본 정확 카운트 5/5).
- 차분의 정체는 **후행 바이트 아티팩트**입니다. 예:
  `_boolean`(225) ↔ `_booleanI`(226), `_float32I`(225) ↔ `_float32`(226),
  `Entered plan mode`(225) ↔ `Entered plan modezE`(226).
  리터럴 본문은 동일하고, **인접한 바이트코드 바이트**가 달라 `strings` 의
  추출 경계가 이동한 것입니다.

**교훈 (다음 사이클 필수 적용)**:

1. `strings` 집합 차분을 **단독 근거로 사용하지 말 것**.
2. 델타 후보는 반드시 `grep -a -o -F <token> <binary> | wc -l` 로
   **원본 바이너리 정확 출현 횟수**를 재확인할 것.
3. 빌드 배너(VERSION · BUILD_TIME · GIT_SHA)를 **먼저 정규화**할 것.
   정규화 없이는 배너 인라인 114개 지점이 전부 가짜 델타로 잡힙니다.

### ERRATA-35-2 (LOW, 환경) — macOS 도구 차이

- `cat -A` 는 BSD `cat` 에 없음 → GNU 전제 금지.
- 바이너리 대상 `tr` 은 `LC_ALL=C` 없이 `Illegal byte sequence` 로 실패.
